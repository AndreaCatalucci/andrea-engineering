# Ideate

Explore the user's problem without turning the session into an interview.

1. Read the request and only the local context needed to understand it.
2. State any consequential assumption instead of asking a question.
3. Generate 3-7 genuinely different options. Include the obvious direction and at least one direction that challenges the premise when useful.
4. Compare them on the few dimensions that matter here, such as value, effort, risk, and reversibility.
5. Recommend the strongest option or combination and explain the tradeoff plainly.

Stay grounded in the project when a repository is available. Distinguish observed facts from inference. Do not invent implementation detail to make an idea look complete.

Work inline unless the user explicitly asks for parallel exploration. Do not route into brainstorming, planning, or implementation automatically. End with the ideas and recommendation, not a menu of workflows.

Default to chat and at most 700 words. Create an artifact only when requested.
