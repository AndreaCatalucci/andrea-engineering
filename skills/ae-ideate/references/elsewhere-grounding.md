# Elsewhere Grounding

Read this only when the ideation subject is outside the current repository.

Synthesize the user's prompt, intake, URLs, briefs, drafts, and pasted material
into the topic's current state, constraints, pains, and useful openings. For an
outside software product, search `docs/solutions/` for genuinely transferable
lessons. Skip repository learnings for non-software topics.

Run web research unless the user explicitly skipped it. Look for prior art,
adjacent solutions, market evidence, and cross-domain analogies. Follow
`web-research-cache.md` for session reuse. Keep external findings separate from
the user's material. Issue intelligence does not apply. Gather Slack context
only when explicitly requested and available.

In surprise-me mode, extract recurring language, tensions, omissions, and
themes from the supplied material, and broaden web research to the domain
landscape. If the supplied material is still too thin to identify any subject,
stop rather than dispatch empty-context agents.

Write a compact summary with only non-empty sections:

- Topic context;
- Past learnings, for software topics only;
- External context, noting cache reuse;
- User-supplied research dossiers or small inline evidence;
- Slack context.

Record thin intake and research failures plainly so generation can widen its
search without pretending the evidence is stronger than it is.
