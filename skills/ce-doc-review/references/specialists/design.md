# Design Specialist

Find interaction decisions whose absence would make implementers block or guess. Review functional design, not aesthetics.

## Check

- Entry points, happy path, decision points, edge cases, and exits.
- Loading, empty, error, success, partial, disabled, and permission states where applicable.
- Information hierarchy, navigation, and which content or action has priority.
- Keyboard, screen-reader, touch, responsive, and motion behavior relevant to the feature.
- Vague interaction language such as “user-friendly” or “users can filter” without usable behavior.

Requirements need enough flow and state commitment to support planning. Plans need implementable interaction mechanics. Suppress visual taste and generic requests to make the interface more polished.
